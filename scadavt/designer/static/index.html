How to design a network

Everything you build is saved as one plain config file — the same file the Python API/CLI uses.

1 · Add nodes

  1. Click + PLC, + MTU, + Switch, + Router. Each appears on the canvas.
  2. Drag any node to move it anywhere — press on it and drag (free movement, no grid snapping).

2 · Wire them (links)

  1. Click 🔗 Connect (it turns blue — you are now in Connect mode).
  2. Click the first node: a dashed line follows your cursor.
  3. Click the second node to create the link. Keep clicking pairs to add more.
  4. Press Esc or right-click to cancel; click 🔗 Connect again to leave Connect mode.

Tip: in real SCADA, PLCs and the MTU connect to a Switch (one LAN); a Router joins two switches into a WAN. A direct PLC↔PLC link is allowed but shown dashed amber, because it is unusual — usually you want each device on a switch.

3 · Configure

  1. Click a node to edit its id and IP in the Properties panel. Give devices on one switch the same subnet (e.g. 10.0.1.x), the MTU 10.0.1.254.
  2. For a PLC, seed is its sensor value (used so rules fire deterministically).

4 · Control rules

In the Rules box, type cross-PLC rules, one per line, then Apply rules:

S1 < 3 => A2 open = when PLC1's sensor (S1) is below 3, open PLC2's actuator (A2). Sx/Ax are PLC x's sensor / actuator.

5 · Validate & run

  1. Validate — checks the network (structure + rules) on the server; errors show in Output.
  2. ▶ Run — builds and runs it live on CORE and reports, per device, whether the MTU reached it and the read-back sensor/actuator values.
  3. Export saves the config file; Import loads one back (lossless) — the same file runs from the CLI with scadavt run.

A quick first network

  1. + MTU, + Switch, + PLC, + PLC.
  2. 🔗 Connect → click MTU then Switch; Switch then PLC1; Switch then PLC2.
  3. Rules: S1 < 3 => A2 open → Apply.
  4. Validate → Run. You should see each device reached and A2 opened.
