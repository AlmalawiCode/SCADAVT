SCADAVT · Network Designer

Design, wire & run a SCADA network

Place controllers on a canvas, wire them, add control logic, and run it on the live CORE emulator — the picture you draw is the same config the Python CLI runs. This guide ends with a full three-PLC example you can copy click-for-click.

◆The parts

Four node types — each PLC becomes a real emulated machine running a Modbus device.

PLC — a controller with a sensor s and actuator a MTU — the master that reads sensors & sends commands (one per network) Switch — one LAN; everything on it shares a subnet Router — joins two switches into a WAN

1Add nodes

  1. Click + PLC, + MTU, + Switch, or + Router in the toolbar — the node appears on the canvas.
  2. Move anything: press a node and drag it anywhere (free movement — no grid snapping).
  3. Select: a single click (without dragging) selects a node and shows its Properties.
  4. Delete: select a node and press Delete (or the 🗑 button).

2Wire them together

  1. Click 🔗 Connect — it turns blue (you're in Connect mode).
  2. Two ways to make a link:
    • Drag from one node and release on another, or
    • Click the first node, then click the second.
    A dashed line follows your cursor while you aim.
  3. Keep going to add more links. Press Esc or right-click to cancel the current link; click 🔗 Connect again to leave Connect mode.
💡
Golden rule: connect each PLC and the MTU to a Switch (that makes one LAN where they can all talk). Use a Router only to join two switches into a WAN.
⚠
A direct PLC↔PLC or PLC↔MTU link is drawn as a dashed amber line. It's allowed, but it's a point-to-point wire — if one node has several of them they fight over the same IP and only one works. For normal networks, go through a Switch.

3Configure addresses

Click a node to edit it in the Properties panel:

  • id — the node's name (e.g. PLC1).
  • IP — put everything on one switch in the same subnet, e.g. 10.0.1.1, 10.0.1.2, …, and the MTU at 10.0.1.254.
  • seed (PLC only) — the sensor's starting value, so your rules fire predictably.

4Add control rules

In the Rules box (right panel), type one rule per line, then press Apply rules:

S1 < 3 => A2 open   # if PLC1's sensor S1 is below 3, open PLC2's actuator A2

Sx is PLC x's sensor, Ax is PLC x's actuator. This is how one PLC's reading drives another PLC's output — cross-PLC control.

💡
No rules = actuators stay at their default (you'll see a=0 after a run). Add rules to make things move.

5Validate & run

  • Validate — checks the whole network on the server; any problems appear in the Output panel.
  • ▶ Run — builds & runs it live on CORE and reports, per device, whether the MTU reached it and the read-back sensor/actuator values.
  • Export — downloads the config file. Import — loads one back (nothing is lost). The exact same file runs from the terminal with scadavt run.

★Worked example — run three PLCs

One MTU reads three PLCs on a switch; a control ring makes each PLC's low sensor open the next PLC's actuator.

a) Add the nodes
  1. + MTU
  2. + Switch
  3. + PLC three times → PLC1, PLC2, PLC3
b) Wire everything to the switch (click 🔗 Connect, then drag each onto SW1)
  • MTU → SW1
  • PLC1 → SW1, PLC2 → SW1, PLC3 → SW1

All four links should be solid grey (through the switch) — no amber dashed lines.

c) Addresses (defaults already fit: PLCs 10.0.1.1/2/3, MTU 10.0.1.254). Leave each PLC's seed at 2 (that's "low").

d) Rules — paste into the Rules box and press Apply rules: 
S1 < 3 => A2 open
S2 < 3 => A3 open
S3 < 3 => A1 open
e) Run — press Validate (should say VALID ✓), then ▶ Run. Expected Output:
RUN ✓ started=true, reached 3/3 PLC1: reachable=true s=2 a=1 PLC2: reachable=true s=2 a=1 PLC3: reachable=true s=2 a=1

Every sensor is 2 (< 3), so every rule fires and every actuator opens (a=1). Change a PLC's seed to 5 and re-run: that PLC's rule no longer fires, and the actuator it targets stays a=0.

⌨The same network from the terminal

The GUI is optional. Export your design to net.json, then:

# validate and run the very same file the designer produced
scadavt validate net.json
scadavt run net.json --live

Or scaffold a three-PLC network without the GUI at all:

scadavt scaffold --plcs 3 -o net.json
scadavt run net.json --live

Same model, same validation, same engine — the GUI just draws it.

?Troubleshooting

You see…Why / fix
reached 1/2 (or similar)A device isn't on a shared LAN. Connect every device to a Switch and give them IPs in the same subnet. Avoid direct device↔device (amber) links.
All a=0 after a runNo rules fired. Add rules and press Apply rules, and make sure the triggering sensor's seed is below the rule's threshold.
INVALID on ValidateRead the listed issues — usually a duplicate IP, a link to a missing node, or a rule referencing an element that doesn't exist.
RUN failed (503)The service can't reach CORE. Start it on a host with the CORE daemon running, or set SCADAVT_CORE_PYTHON.
Can't reach the serviceCheck the Service base field (blank = same origin) and, for a remote service, the Auth token.
